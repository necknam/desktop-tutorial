한국수자원공사 인재개발규정 · 시범 전처리 전달본 V01
==================================================

1. 이 전달본의 목적

규정 담당자가 확보한 PDF를 읽고, DB에 저장할 수 있는 행 단위 자료와
다시 처리할 수 있는 코드를 만드는 첫 시범 작업입니다.

입력: 인재개발규정(2024년도 12월 개정).pdf, 22쪽
처리: 문서 추출 → 본문/부칙/별표/서식 구분 → 원문 위치 연결 → DB 행 생성
출력: JSON·CSV, PostgreSQL용 테이블 생성/적재 SQL, 검토 화면, 검증 결과

규정 담당자의 범위는 이 자료의 전처리·검토·전달입니다.
오호민 팀원의 교육 데이터 통합, Supabase 적재, GitHub 전달은 후속 작업입니다.
이 전달본은 Supabase에 접속하거나 GitHub에 게시하지 않습니다.

2. 사용자가 먼저 볼 파일

검토안내.html
  브라우저에서 열어 처리 결과 → 검토 사항 → 조항 → 별표 → 필드 순으로 확인합니다.
  원문 이미지/링크는 source 폴더에 있으므로 ZIP을 먼저 전체 압축 해제합니다.
  HTML 파일만 이동하면 원문 이미지와 PDF 링크가 연결되지 않습니다.
  JSON의 모든 필드를 읽기 전에 이 파일을 먼저 보세요.

우선 검토할 3가지
  ① 별표 2·3: 병합 표와 도식의 자동 추출 내용을 원문과 비교
  ② 제10조 제3항: 2028-01-01 시행일과 부칙 제1조 연결 확인
  ③ 제28조 제4항: “다음 각호에 따른다.” 이후 호 내용이 원문에서 확인되지 않는 점

2024-12-26 개정본의 일반 시행일은 2025-01-01입니다.
이것이 2026년 현재 최신 개정본인지, 적용 종료일이 언제인지는 이번 작업에서 확인하지 않았습니다.
이번 파일에 포함된 과거 부칙 23개를 23개의 과거 전체 규정으로 취급하지 않습니다.

3. 파일별 용도

data/*.json
  프로그램·DB 통합용 기준 자료입니다. 필드 이름은 기존 규정 ERD와 맞췄습니다.
  NULL은 미확인/미생성, []는 목록이 비어 있음을 뜻합니다.

data/*.csv
  같은 행을 표로 확인하는 보조 파일입니다. UTF-8 BOM으로 저장했습니다.
  CSV의 빈 문자열과 NULL을 구별하기 위해 NULL은 \N으로 표기했습니다.
  일반 CSV 업로드에서 \N이 자동 NULL로 바뀐다고 가정하지 마세요.
  통합 담당자는 JSON 또는 SQL을 우선 사용하고 CSV 사용 시 NULL/JSON/BOOLEAN을 변환합니다.

raw/pages.json
  22쪽의 원문 추출 결과·행 번호·좌표를 보존합니다.
  본문 줄바꿈과 개정 주석을 임의로 고치거나 지우지 않았습니다.
  쪽번호는 구조화 본문에서 제외하지만 raw에는 보존했습니다.

raw/tables.json
  자동 검출 표 6개와 셀·좌표입니다. None은 병합 또는 미추출입니다.
  None을 “해당 없음”으로 단정하지 마세요. 빈 문자열과도 다릅니다.

source/
  원본 PDF의 동일 바이트 사본과 표·시행일 페이지 이미지입니다.
  원래 다운로드한 파일을 수정하지 않았습니다.

profile.json
  이 개정본에 한정하는 확인 정보입니다. 원문 SHA-256, 시행일, 시범 규칙을 담습니다.
  다운로드 시각: 2026-10-01T09:39:00+09:00 / 사용자 제공 / 분 단위
  초 00은 날짜·시각 형식에 맞춘 표기이며 실제 다운로드 초를 확인했다는 의미가 아닙니다.
  다른 규정·다른 개정본에는 이 프로필을 그대로 적용할 수 없습니다.

schema.json
  기존 HR_Example_ERD.html의 규정 관련 9개 테이블·필드와 실제 FK 연결 정의입니다.
  데이터 구조의 기준이므로 SQL·필드 설명은 이 파일에서 생성합니다.

report/field_guide.csv
  필드 이름, 한글 설명, 자료형, 필수/선택, PK/FK, 주의할 값을 따로 비교합니다.

report/manifest.json
  원문 해시, 처리 시각, 다운로드 시각의 출처·정밀도, ID, 도구 버전을 기록합니다.
  ALIO 내부규정 목록 URL은 원본 파일의 직접 다운로드 URL과 구분합니다.

report/validation.json / review_issues.json / reprocessing_check.json
  실행한 자동 검사 결과 / 사용자 원문 검토 사항 / 재처리·CSV 왕복·파일 연결 검사 결과입니다.
  자동 검사가 통과했다고 규정 해석과 사용자 검토가 완료된 것은 아닙니다.

sql/01_schema.sql
  전달용 독립 스키마 hr_regulation_pilot과 9개 테이블을 생성합니다.
sql/02_data.sql
  해당 스키마에 데이터를 넣습니다. 같은 ID가 있으면 해당 행을 갱신합니다.
  전체 적재는 BEGIN/COMMIT으로 묶었습니다. DROP/DELETE는 포함하지 않습니다.

preprocess.py / validate.py / requirements.txt
  재처리 코드 / 검증 코드 / 필요한 직접 의존성 버전입니다.

4. 테이블 연결을 이해하는 순서

기관 1건
  → 규정 1건: 인재개발규정이라는 문서의 이름·분류
  → 개정본 1건: 22차·개정일·시행일·검토 상태
  → 파일 1건: 확보한 PDF·해시·다운로드 시각·공개 여부
  → 원문 항목 202건: 장·조·항·부칙·별표·서식·검출 표
  → 검색 후보 106건: 답변 근거를 찾기 위한 텍스트 묶음(벡터 아님)
  → 검색 근거 연결 106건: 각 후보가 어느 원문 항목/행에서 왔는지

적용 조건 1건은 제10조 제3항의 예외 시행일을 부칙 근거에 연결합니다.
규정 참조는 직접 표기된 별표/서식/규정명에 한해 수집합니다.
다른 규정명의 줄바꿈 등은 원문 그대로 보존하며 외부 문서 참조는 unresolved입니다.
모든 동일 규정 조 번호와 상대적 “같은 규정” 참조를 자동 해결했다고 간주하지 않습니다.

상위 조문에 통합 원문을 보존하고 ① 등 항 번호가 있는 조문은 하위 항으로도 저장했습니다.
항이 있는 조문은 항 단위로 검색 후보를 생성하여 상위 조문과의 중복 검색을 줄였습니다.
호·목은 상위 항/조의 텍스트에 보존했습니다. 이번 시범에서 별도 호·목 노드로는 나누지 않았습니다.
표 노드의 grid와 좌표는 source_locator JSON에도 담습니다.
표의 의미 판별·교육 인정 여부·직원 수준 판단을 자동 확정하지 않습니다.

5. 현재 ERD와의 관계 및 통합 시 확인할 내용

기관 ID
  한국수자원공사 1건입니다. 전달본 ID는 안정적인 UUID이며 공식 ALIO 기관 코드가 아닙니다.
  통합 DB에 이미 기관 ID가 있으면 재처리 옵션 --institution-id로 해당 값을 사용합니다.
  여러 파일에서 기관 정보가 중복 생성되지 않도록 같은 기관 ID를 사용해야 합니다.

자료형
  DATETIME → TIMESTAMPTZ, JSON → JSONB, TINYINT(1) → BOOLEAN으로 변환했습니다.
  기존 HR_Example_ERD.html을 수정하거나 public의 서비스 테이블을 변경하지 않았습니다.

미생성 임베딩
  기존 ERD의 embedding_model은 필수지만 아직 모델·벡터가 정해지지 않았습니다.
  전달용 스키마에서 이 필드만 NULL을 허용합니다. 팀 스키마 변경을 확정한 것은 아닙니다.
  통합 시 미생성 상태의 표현을 확인하거나, 규정 핵심 테이블부터 적재하고 검색 후보는 보류할 수 있습니다.
  벡터 열/인덱스/API 호출은 포함하지 않았습니다. 1536차원을 규정에도 확정하지 않았습니다.
  하이브리드 검색은 시범 질문과 비교한 후 별도로 결정합니다.

검색 상태
  pending_review: 사용자 검토 전 일반 후보
  needs_review: 표·원문 내용 추가 검토가 필요한 후보
  not_for_answer: 본조 삭제 조문
  active인 후보는 없습니다. 이 전달본을 즉시 운영 검색에 사용한다고 가정하지 마세요.
  후속 검색 연동 시 공개 여부와 이용 상태, 개정본/항의 시행일을 함께 확인합니다.
  제10조 제3항의 2028 시행일을 상위 조문에 통째로 적용하지 않도록 주의합니다.
  과거 부칙을 새 규정의 현재 교육 인정 기준으로 자동 적용하지 않습니다.

원문 저장
  storage_key는 전달 폴더의 상대 경로입니다. Supabase Storage 업로드 완료 경로가 아닙니다.
  실제 파일 저장소에 업로드할 때 대상 위치를 매핑해야 합니다.
  원문 해시로 파일이 동일한지 확인할 수 있습니다.

나머지 데이터
  직원·평정·교육 추천 데이터의 테이블이나 값은 변경하지 않았습니다.
  규정 필드를 직원 정보의 직급·직군 코드에 자동 매핑하는 것은 후속 협의 사항입니다.
  내부 학습 인정기준이 미확보여도 공개 규정의 기준시간과 미확인 내용을 구분해 안내할 수 있습니다.
  가상 인정기준을 이 공식 규정 데이터에 섞지 않았습니다.

6. 개발 담당자가 재처리하는 방법

패키지 설치와 명령 실행은 개발 담당자가 환경을 확인한 후 수행합니다.
Python 3.10 이상에서 사용할 수 있도록 작성했으며 실제 검증 환경은 manifest에 기록했습니다.
전달본 폴더를 작업 위치로 연 다음:

  python -m pip install -r requirements.txt

  python -X utf8 preprocess.py --input "source/인재개발규정(2024년도 12월 개정).pdf" --output "재처리결과"

  python -X utf8 validate.py --output "재처리결과"

새 output 폴더에 결과를 생성하므로 원본/기존 전달본을 보존할 수 있습니다.
기본 --output은 이 코드가 있는 폴더이며 결과 파일을 다시 생성합니다.
같은 원문·기관 ID·프로필은 같은 ID를 생성합니다. 처리 시각/created_at은 실행마다 바뀝니다.
단순 반복 적재 시 같은 PK를 갱신하므로 같은 자료의 중복 행은 추가되지 않습니다.
서버에서 새 색인을 활성화하거나 운영 데이터 삭제를 자동 처리하지 않습니다.
다른 파일을 넣으면 해시 확인 단계에서 중단합니다. 신규 규정 처리는 별도 프로필 검토가 필요합니다.

7. 통합 담당자의 적재 순서

현재 전달본은 Supabase에서 실제 실행하지 않았습니다.
먼저 schema.json과 필드 설명을 기존 팀 DB 구조와 비교합니다.
독립 스키마로 시범 적재할 경우 01_schema.sql → 02_data.sql 순서로 검토 후 실행합니다.
같은 이름의 스키마가 이미 다른 구조로 존재하면 그대로 실행하지 말고 대응 구조를 확인합니다.
01_schema는 새 스키마/테이블을 만들고, 02_data는 행을 추가하거나 같은 ID의 행을 갱신합니다.
기존 팀 테이블에 넣을 경우 public 테이블 이름/필드/기관 ID/이용 상태를 먼저 매핑합니다.
직원·교육 등 다른 팀 데이터는 통합 담당자가 함께 검토합니다.

자동 검사에서 실행한 것
  원문 22쪽, 본문 41개 조항, 부칙·별표·서식 경계와 원문 행 위치
  페이지를 넘는 제5조·제27조, 예외 시행일, 별표1 시간 배열·주석
  필수값·최대 길이·FK 연결, 검색 후보의 원문/해시, 미생성 임베딩 상태
  SQLite 임시 메모리 DB에서 반복 적재와 외래키 무결성 검사

이것은 PostgreSQL/Supabase 서버 실행 검사나 실제 검색 품질 평가가 아닙니다.
인증·권한·API 노출·벡터 열 설계는 이 규정 데이터 시범 전처리 범위에 포함하지 않았습니다.
임시 DB 파일을 생성하거나 전달하지 않았습니다.
원본 PDF 사본/이미지는 팀 내부 전달용으로 포함했으며 GitHub에 자동 등록하지 않았습니다.
GitHub에 전달할 항목은 통합 담당자가 원문 이용 조건과 팀 지침에 맞게 선택합니다.
