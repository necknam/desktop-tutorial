1. 데이터셋 개요

이 데이터는 GrowPath AI의 계획 구체화, 사전 역량 설문 생성, 맞춤형 학습 로드맵 생성을 지도 미세조정(SFT) 방식으로 학습시키기 위한 대화형 예시입니다.

입력 데이터

  • system: 에이전트 역할, 작업 지침, 금지 조건, 출력 JSON 규격
  • user: 프로젝트 계획·직무·가용 시간·스킬 진단·DB 검색 결과 등 작업 맥락
  • user 입력은 일반 문장뿐 아니라 JSON 문자열, 계획 문서, 대화 이력을 포함할 수 있음

정답 데이터

  • assistant: 모델이 학습해야 할 목표 응답
  • 계획 구체화는 구조화 JSON, 설문 생성은 JSON 배열, 로드맵 생성은 JSON 객체 형태를 사용
  • 로드맵 응답에는 마일스톤과 실제 자원 ID, 규정 인용 등 구조화 필드가 포함됨
파일명과 실제 건수는 다릅니다. 파일명은 3,000건을 나타내지만, 업로드된 JSONL을 직접 읽어 확인한 레코드는 2,603건입니다. 따라서 현재 파일만 근거로 “3,000건이 모두 들어 있다”고 기술하면 부정확합니다.

3. 서비스 흐름과 태스크별 학습 목표

① 프로젝트 계획 구체화

초기 계획과 사용자 대화에서 합의한 학습 시간·우선순위·기술 범위를 반영해 최종 계획을 구조화합니다.

  • 주요 입력: 초기 계획, 대화 이력, 허용된 DB 스킬 태그, 출력 스키마
  • 주요 출력: refined_plan, project_goal, project_scope, tech_stack, milestones, key_issues, deliverables, validation_criteria
  • 학습 포인트: 대화에서 확정된 조건을 계획에 반영하고, 정해진 스킬 태그나 출력 필드를 임의로 바꾸지 않음

② 사전 역량 설문 생성

확정 계획과 슬롯 목록을 이용해 자기보고식 1~5점 척도에 맞는 질문을 만듭니다.

  • 주요 입력: project_plan, project_goal, slots
  • 주요 출력: sequence_no, skill_id, question을 가진 JSON 배열
  • 학습 포인트: 각 질문에 지정 스킬과 세부 주제를 포함하고, 서술형 지시 대신 이해도를 묻는 의문문을 생성

③ 맞춤형 로드맵 3안 생성

같은 프로젝트 맥락을 서로 다른 전략으로 풀어내되, 실제 검색 결과와 승인된 규정 근거의 범위를 벗어나지 않도록 합니다.

전략중점구별되는 출력 특성
agent_practical실무 적용실행 과제, 구현 결과물, 테스트·검증 중심
agent_certified이론·자격기본 원리, 표준 아키텍처, DB 검색 결과에 존재하는 자격증 중심
agent_fasttrack단기 납기핵심 병목, 우선순위, 불필요한 학습 범위 축소

4. JSONL 레코드 형식

JSONL은 한 줄에 JSON 객체 하나를 저장합니다. 병합본과 두 분할 파일의 각 객체는 최상위 키 messages를 가지며, 메시지 배열은 system/user/assistant 순서로 구성됩니다.

{
  "messages": [
    {
      "role": "system",
      "content": "에이전트 역할, 수행 규칙, 출력 스키마..."
    },
    {
      "role": "user",
      "content": "프로젝트 입력, 대화 이력, 진단 결과, DB 검색 결과..."
    },
    {
      "role": "assistant",
      "content": "모델이 학습할 정답 응답..."
    }
  ]
}

필드 의미

필드자료형용도점검 사항
messages배열한 학습 예시의 대화 이력필수이며 메시지 구조가 일관적인지 확인
role문자열발화 역할현재 파일은 system, user, assistant를 각 1회 포함
content문자열지침, 입력 맥락, 목표 응답JSON 응답은 문자열 안에 JSON 텍스트로 들어갈 수 있음
중요: assistant의 content가 JSON 형식인 경우, 바깥쪽 JSONL 파싱 성공과 content 내부 JSON 파싱 성공은 서로 다른 검증입니다. 두 단계 모두 확인해야 합니다.

6. 근거 통제와 오류 방지 규칙

  • 자원 추천 근거: 강좌·도서·자격증은 user 컨텍스트에 포함된 실제 DB 검색 결과만 사용하도록 system 지침에 명시되어 있습니다.
  • 식별자만 출력: 로드맵의 추천 자원 배열에는 제목이나 URL을 직접 작성하기보다 course_id, isbn, cert_id를 사용하도록 지시합니다.
  • 규정 승인 상태 구분: regulation_rag.approved만 확정 규정 근거로 인용하며, review_only는 확정 근거로 사용하지 않도록 되어 있습니다.
  • 근거가 없을 때: 승인 규정이 없으면 regulation_citations: [], regulation_summary: "규정 확인 필요"로 응답하도록 규정합니다.
  • 역량 점수 해석: 1~5점 자기보고 결과는 이해도 응답이며, 실무 능력이 검증되었다는 의미로 과장하지 않도록 합니다.
  • 계획 기간과 성과: 기간은 추정치로 취급하고, 측정되지 않은 성능 향상이나 합격을 보장하지 않도록 지시합니다.

이 항목들은 system 지침에 존재하는 설계 의도입니다. 지침에 규칙이 있다는 사실이 실제 모델의 오류율 0% 또는 규칙 준수 100%를 입증하는 것은 아닙니다.
