2. 전체 하이퍼파라미터 심층 기술 해설 (In-Depth Technical Breakdown)

learning_rate 0.0001 (1e-4)
학습률 (가중치 갱신 보폭 크기)

오차 역전파를 통해 계산된 기울기(Gradient)를 LoRA 어댑터 가중치에 얼마만큼 반영할지 결정하는 가장 핵심적인 파라미터입니다.

  • 27B 적용 근거: 7B 모델은 2e-4까지 견디지만, 27B는 레이어가 깊어 1.5e-4를 초과하면 초반에 기존 지식 손실 및 가중치 발산(NaN)이 발생합니다.
  • 미세 조정: 초반 150스텝 내 Loss 진동 시 0.00008(-0.00002) 하향, 1에포크 후에도 수렴 정체 시 0.00012(+0.00002) 상향.
lr_scheduler_type cosine
학습률 스케줄러 (보폭 감쇄 함수)

학습 진행(Step)에 따라 학습률을 점진적으로 감소시키는 알고리즘입니다.

  • Cosine 채택 이유: Linear 방식은 선형으로 감소하여 끝점에서 튕길 수 있으나, Cosine은 코사인 곡선을 그리며 0에 수렴하듯 완만하게 감쇄합니다.
  • 엔지니어링 효과: 학습 후반부에 모델이 미세한 제약(예: 부분수정 시 원형 보존, "확인 필요" 표기)을 안정적으로 고정시키는 데 최적입니다.
warmup_ratio 0.06 (6%)
워밍업 비율 (초반 보폭 점진 증폭)

학습 시작 직후 0에서 설정된 최대 학습률(0.0001)까지 선형적으로 서서히 끌어올리는 준비운동 구간의 비율입니다.

  • 동작 산술: 총 972스텝 중 초반 약 58스텝 동안 학습률이 0에서 0.0001로 완만하게 증가합니다.
  • 필수 이유: LoRA 어댑터 초기화 직후에는 그래디언트 오차가 매우 크므로, AdamW 통계량이 쌓일 때까지 완충하여 발산과 급발진을 방지합니다.
num_train_epochs 3.0
전체 데이터셋 학습 반복 횟수

전체 5,184건의 데이터셋을 모델이 몇 번 반복해서 학습할지 결정합니다.

  • 2에포크 vs 3에포크: 2에포크는 문장이 자연스럽지만 복합 제약 준수율이 95% 수준에 머뭅니다. 3에포크까지 진행되어야 스키마 정합성이 99.5%로 고정됩니다.
  • 과적합 안전성: 단일 템플릿이 아닌 6개 멀티태스크가 교차 정규화(Regularization) 역할을 수행하므로 3에포크에서도 암기식 과적합이 오지 않습니다.
per_device_train_batch_size 2
GPU 물리적 1회 처리 샘플 수

GPU VRAM에 동시에 올려 순전파(Forward)와 역전파(Backward)를 수행하는 마이크로 배치 크기입니다.

  • VRAM 제약: 2048 토큰 기준 Qwen-27B(4-bit)는 배치 2일 때 약 32~36GB VRAM을 점유하여 A100(80GB)에서 안정적으로 가동됩니다.
  • OOM 처방: 만약 순간적인 메모리 스파이크로 OOM이 발생하면 1로 즉시 낮추고 누적 스텝을 16으로 올립니다.
gradient_accumulation_steps 8
그래디언트 누적 스텝 수

VRAM 한계로 물리적 배치를 크게 잡지 못할 때, 가중치를 즉시 갱신하지 않고 오차를 N회 모았다가 한 번에 업데이트하는 기법입니다.

  • 유효 배치 수식: Effective Batch Size = Batch Size(2) × Accumulation(8) = 16.
  • 엔지니어링 근거: 유효 배치가 16은 되어야 손실 함수 곡선이 요동치지 않고 부드러운 하강 곡선을 유지할 수 있습니다.
lora_r (Rank) 32
LoRA 저순위 행렬 차원 크기

고차원의 가중치 변화 행렬을 저차원 행렬 두 개의 곱(W = A × B)으로 분해할 때의 중간 차원 크기입니다.

  • 표현 용량: r=8, 16은 단순 어조 변경에 적합하나, 사내 규정 감사·부분수정·관점 분기 등 복잡한 논리를 담기 위해서는 r=32가 필수적입니다.
  • 미세 조정: 3에포크 후에도 복잡한 지시 이행이 미흡하면 64로 2배 확장하고, 메모리가 부족하면 16으로 축소합니다.
lora_alpha 64
LoRA 스케일링 계수

학습된 어댑터 가중치를 원본 가중치에 더할 때 적용하는 가중치 배율입니다. 실제 적용 스케일은 (lora_alpha / lora_r)입니다.

  • 비율 고정 원칙: alpha = 64, r = 32일 때 스케일링 팩터는 64 / 32 = 2.0입니다.
  • 연동 규칙: Rank(r)를 64로 늘리면 alpha도 128로 함께 올려 항상 2.0 비율을 유지해야 안정적인 업데이트 강도가 유지됩니다.
lora_dropout 0.05 (5%)
어댑터 드롭아웃 확률

학습 도중 LoRA 어댑터의 입력 뉴런 중 5%를 무작위로 0으로 만들어 특정 경로 의존성을 차단하는 정규화 기법입니다.

  • 과적합 방지: 데이터셋의 예시 문구를 그대로 복사해 출력하는 '템플릿 암기'를 방지하고 일반화된 추론을 유도합니다.
  • 조정 기준: 과적합 징후 시 0.08로 상향, 반대로 JSON 괄호나 쉼표가 깨지는 문법 오류 발생 시 0.02로 하향합니다.
target_modules all-linear
LoRA 어댑터 삽입 대상 레이어

트랜스포머 아키텍처 내 어떤 선형 레이어에 LoRA 가중치를 주입할지 지정합니다.

  • 적용 범위: Attention 프로젝션(q, k, v, o)뿐만 아니라 MLP 피드포워드 레이어(gate, up, down)까지 전수 포함합니다.
  • 효과: Attention에만 넣으면 문체만 바뀌지만, MLP까지 주입해야 새로운 도메인 지식(사내 규정, 엔지니어링 용어)이 모델 깊숙이 정렬됩니다.
max_seq_length 2048
최대 토큰 시퀀스 길이

입력 프롬프트와 출력 답변을 합산한 최대 토큰 수입니다. 2048을 초과하는 텍스트는 자동으로 잘립니다(Truncation).

  • 충분성 검증: GrowPath의 멀티턴 대화 및 4단계 중첩 JSON 로드맵은 최대 1,400~1,700 토큰 내외이므로 2048로 완벽히 수용됩니다.
  • 메모리 주의: 길이를 4096으로 올리면 Self-Attention 연산량이 O(N²)으로 증가하여 VRAM이 급증하므로 2048 유지가 최선입니다.
optim paged_adamw_8bit
8비트 페이징 옵티마이저

옵티마이저 상태값(1차/2차 모멘텀)을 8비트로 양자화하고, VRAM 부족 시 시스템 RAM으로 페이징(오프로드)하는 BitsAndBytes 알고리즘입니다.

  • 메모리 절감: 표준 AdamW 32비트 대비 옵티마이저 메모리 점유율을 75% 절감하여 27B 모델 학습 시 VRAM을 대폭 확보합니다.
  • 안정성: 메모리 스파이크 발생 시 프로세스가 죽지 않고 시스템 RAM을 완충재로 사용하여 OOM 크래시를 원천 방어합니다.
weight_decay 0.01
가중치 감쇠 (L2 정규화 계수)

가중치들이 지나치게 커지지 않도록 손실 함수에 가중치 크기에 비례하는 페널티를 부여하는 기법입니다.

  • 역할: 특정 가중치 하나가 비정상적으로 거대해져 발생하는 과적합을 방지하고 일반화 성능을 높입니다.
  • 조정: 0.01은 표준 안전값입니다. 모델이 너무 뻣뻣하게 학습되지 않으면 0.001로 내리고, 과적합이 심하면 0.05로 올립니다.
max_grad_norm 0.3
그래디언트 클리핑 임계치

역전파 중 산출된 그래디언트 벡터의 L2-Norm(크기)이 임계치를 초과할 경우, 방향은 유지한 채 크기만 강제로 잘라내는 안전장치입니다.

  • NaN 방어: 27B 대형 모델에서 이상치(Outlier) 배치가 인입되었을 때 가중치가 파괴되거나 Loss가 NaN으로 튀는 현상을 막아줍니다.
  • 권장값: 표준값(1.0)보다 보수적인 0.3을 유지하여 극단적인 기울기 폭발을 완전히 억제합니다.
bf16 & precision bf16=True
Bfloat16 혼합 정밀도 연산

지수 비트(Exponent)를 FP32와 동일한 8비트로 유지하여 언더플로우/오버플로우 위험을 제거한 16비트 부동소수점 포맷입니다.

  • FP16과의 차이: FP16은 지수 비트가 5비트뿐이라 Loss 스케일링이 실패하면 NaN이 빈번하지만, BF16은 동적 범위가 넓어 극도로 안정적입니다.
  • 하드웨어: Ampere 아키텍처(A100)의 Tensor Core에서 네이티브 가속되므로 필수적으로 bf16=True를 적용합니다.
gradient_checkpointing True
그래디언트 체크포인팅 (필수 플래그)

순전파 때의 모든 중간 활성화 맵(Activation)을 메모리에 들고 있지 않고, 역전파 시 필요한 부분만 다시 계산(Recomputation)하는 기법입니다.

  • 메모리 혁신: 연산 속도가 약 20% 느려지는 대신, 활성화 맵 VRAM 점유율을 60% 이상 절감시킵니다.
  • 27B 필수: 이 플래그를 켜지 않으면 2048 토큰 시퀀스에서 A100(80GB) 환경이라도 즉시 OOM이 발생합니다.

3. 실전 학습 증상별 원포인트 긴급 처방전

증상 1: 학습 시작 100스텝 이내에 Loss가 NaN이 되거나 10 이상 폭발 Gradient Explosion
원인: 초기 학습 보폭이 과도하거나 초반 그래디언트 쇼크로 인해 가중치 맵이 깨짐.
처방: learning_rate = 0.00008 (하향) + warmup_ratio = 0.10 (초반 97스텝 웜업 연장) + max_grad_norm = 0.3 재확인.
증상 2: 1에포크(324스텝) 종료 시점에도 Loss가 2.5 이하로 떨어지지 않음 Underfitting / Stagnation
원인: 학습 보폭이 너무 보수적이어서 Qwen-27B 베이스 모델의 기본 지식 맵을 깨지 못함.
처방: learning_rate = 0.00012 (상향) + weight_decay = 0.001 (정규화 완화).
증상 3: JSON 파싱 성공률은 100%이나, 모든 답변의 코치 조언이 동일 문구로 고착됨 Template Overfitting
원인: LoRA 어댑터 가중치가 특정 템플릿 슬롯 패턴에 과적합됨.
처방: lora_dropout = 0.08 (상향) + 3에포크(972스텝) 대신 2에포크(648스텝) 체크포인트를 최종 배포 모델로 채택.
증상 4: 학습 도중 CUDA Out of Memory (OOM) 충돌로 프로세스 강제 종료 VRAM Allocation Failure
원인: 2048 토큰 멀티턴 시퀀스의 역전파 활성화 맵(Activation Map) 메모리 초과.
처방: per_device_train_batch_size = 1 + gradient_accumulation_steps = 16 + gradient_checkpointing = True 재확인.
